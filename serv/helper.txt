P1 — Fibonacci using Recursion and Iteration
File: P1.cpp
What does the program do?
It calculates the nth Fibonacci number using two methods:
- Recursive approach: calls the same function repeatedly.
- Iterative approach: calculates the result using a loop.
The Fibonacci sequence is:

0, 1, 1, 2, 3, 5, 8, 13, 21 ...

Each number is the sum of the previous two numbers.
Function-by-function explanation
1. fibonacciRecursive(int n)

Purpose: Calculate the nth Fibonacci number using recursion.

How it works:
1. Checks whether n <= 1.
2. If true, returns n (base condition).
3. Otherwise, calls itself with n-1 and n-2.
4. Adds both returned values.
return fibonacciRecursive(n - 1) +
       fibonacciRecursive(n - 2);


Example: fibonacciRecursive(4)
fib(4)
= fib(3) + fib(2)
= 2 + 1
= 3


2. fibonacciIterative(int n)

Purpose: Calculate the nth Fibonacci number without recursion.

How it works:
1. Returns n if n <= 1.
2. Initializes a = 0 and b = 1.
3. Uses a loop from i = 2 to n.
4. Calculates c = a + b.
5. Updates a = b and b = c.
6. Returns b.
3. main()

Purpose: Control the program.
- Accepts the value of n.
- Rejects negative input.
- Calls both Fibonacci functions.
- Displays both results.
Function summary
Function	Purpose
fibonacciRecursive()	Calculates Fibonacci using recursion
fibonacciIterative()	Calculates Fibonacci using a loop
main()	Takes input and displays results

Complexity
Method	Time	Auxiliary space
Recursive	O(2ⁿ) upper bound	O(n)
Iterative	O(n)	O(1)

Viva point
 The iterative approach is more efficient because it avoids repeated calculations.

P2 — Huffman Encoding using Greedy Strategy
File: P2.cpp
What does the program do?
Huffman Encoding is a lossless data compression algorithm.

It assigns:
- Short binary codes to frequently occurring characters.
- Longer binary codes to less frequently occurring characters.
For example, a character appearing 50 times should generally receive a shorter code than a character appearing once.
Important data structures
1. struct Node

Represents a node of the Huffman tree.

It stores:
Variable	Purpose
ch	Character
freq	Character frequency
left	Pointer to left child
right	Pointer to right child

2. struct Compare

Used by the priority queue to arrange nodes by frequency.
bool operator()(Node* a, Node* b) {
    return a->freq > b->freq;
}


This makes the priority queue behave like a min-priority queue: the node with the smallest frequency is selected first.
Function-by-function explanation
1. Node(char character, int frequency)

This is the constructor of the Node structure.
- Assigns the character.
- Assigns its frequency.
- Initializes left and right pointers to nullptr.
2. operator()(Node* a, Node* b)

Purpose: Compare two nodes.

Returns true when node a has a higher frequency than node b, allowing the priority queue to select the minimum-frequency node first.

3. generateCodes(Node* root, string code, unordered_map<char, string>& huffmanCode)

Purpose: Generate binary Huffman codes by traversing the tree.

How it works:
1. If the root is null, return.
2. If the node is a leaf, store its code.
3. Traverse the left child by adding 0.
4. Traverse the right child by adding 1.
generateCodes(root->left, code + "0", huffmanCode);
generateCodes(root->right, code + "1", huffmanCode);


4. printCodes(const unordered_map<char, string>& huffmanCode)

Purpose: Display each character and its generated Huffman code.

It iterates through the map and prints character-code pairs.

5. encode(const string& text, const unordered_map<char, string>& huffmanCode)

Purpose: Convert the original input string into a binary encoded string.

How it works:
1. Creates an empty string called encoded.
2. Visits each character in the original text.
3. Finds its corresponding Huffman code.
4. Appends that code to the encoded string.
5. Returns the final encoded string.
6. main()

Purpose: Execute the complete Huffman encoding process.

Steps:
1. Accept the input string.
2. Count the frequency of each character.
3. Create a priority queue.
4. Insert a node for each character.
5. Repeatedly remove the two minimum-frequency nodes.
6. Combine them into a new parent node.
7. Insert the parent back into the queue.
8. Generate Huffman codes.
9. Encode the original string.
10. Display original and encoded sizes.
Function summary
Function / Structure	Purpose
Node()	Initializes a Huffman tree node
operator()()	Compares node frequencies
generateCodes()	Generates binary codes
printCodes()	Displays generated codes
encode()	Encodes the input string
main()	Controls the complete algorithm

Complexity
For \(k\) distinct characters:
- Time: O(k log k)
- Space: O(k) for the tree and code structures, excluding the encoded output.
Code issue
 If the input contains only one distinct character, generateCodes() assigns an empty string as its code. A robust implementation should assign that character a code such as 0.

P3 — 0/1 Knapsack using Dynamic Programming
File: P3.cpp
What does the program do?
The Knapsack problem selects items to maximize total value without exceeding the available weight capacity.

Each item has:
- Weight
- Value
0/1 means: An item can either be selected once or not selected at all. It cannot be selected multiple times.

Example:
Item	Weight	Value
1	2	10
2	3	20
3	4	30

If capacity is 5, the best selection is items 1 and 2, with total value 30.
Function-by-function explanation
This program does not define separate user-defined functions. The complete algorithm is implemented inside main().

1. Input section
cin >> n;


Accepts the number of items.

Then it reads:
- Item weights into weight.
- Item values into value.
- Knapsack capacity.
2. DP table creation
vector<vector<int>> dp(
    n + 1,
    vector<int>(capacity + 1, 0)
);


Creates a two-dimensional dynamic programming table.

Meaning:
- Rows represent the number of items considered.
- Columns represent the available capacity.
- dp[i][w] represents the maximum value achievable using the first i items with capacity w.
3. DP table construction

The outer loop processes each item.

The inner loop checks every possible capacity.

First, it assumes the item is excluded:
dp[i][w] = dp[i - 1][w];


Then, if the item fits, it checks whether including it gives a better result:
dp[i][w] = max(
    dp[i][w],
    value[i - 1] +
    dp[i - 1][w - weight[i - 1]]
);


This is the central recurrence:
\[
DP[i][w] =
\max(DP[i-1][w],\ value_i+DP[i-1][w-weight_i])
\]

The inclusion option is considered only when the item fits.

4. Maximum value
dp[n][capacity]


Displays the maximum achievable value using all items within the given capacity.

5. Selected item identification

The program moves backwards through the DP table.
if (dp[i][w] != dp[i - 1][w])


If the value changes, item i was selected.

It prints the item number and subtracts its weight from the remaining capacity.
Function summary
Function	Purpose
main()	Reads input, builds DP table, calculates maximum value and identifies selected items

Complexity
- Time: O(n × W)
- Space: O(n × W)
Here, n is the number of items and W is the capacity.

Viva point
 Dynamic Programming avoids recalculating the same subproblems by storing previously calculated results.

P4 — N-Queens using Backtracking
File: P4.cpp
What does the program do?
The N-Queens problem places N queens on an N × N chessboard so that no two queens attack each other.

A queen can attack:
- Horizontally
- Vertically
- Diagonally
This program places the first queen at a user-specified column in the first row, then tries to place the remaining queens.
Function-by-function explanation
1. isSafe(vector<vector<int>>& board, int row, int col)

Purpose: Check whether a queen can safely be placed at a given position.

It checks three directions:
- Same column: checks whether another queen is above.
- Left diagonal: checks the upper-left diagonal.
- Right diagonal: checks the upper-right diagonal.
If any queen is found, it returns false.

Otherwise, it returns true.

Why does it only check upwards? Because the algorithm places queens row by row, so all previously placed queens are in earlier rows.

2. solve(vector<vector<int>>& board, int row)

Purpose: Place queens recursively using backtracking.

How it works:
1. If row == n, all queens have been placed, so return true.
2. Try each column in the current row.
3. Call isSafe() to check the position.
4. If safe, place a queen by setting board[row][col] = 1.
5. Recursively solve the next row.
6. If the recursive call fails, remove the queen and try another column.
board[row][col] = 0;


This is the backtracking step.

3. main()

Purpose:
- Accepts board size N.
- Creates an N × N matrix initialized with zeros.
- Accepts the first queen's column.
- Places the first queen in row 0.
- Calls solve(board, 1).
- Displays the solution if one exists.
Function summary
Function	Purpose
isSafe()	Checks whether a queen can be placed safely
solve()	Places queens recursively using backtracking
main()	Creates the board, places the first queen and displays the result

Complexity
- Worst-case time: commonly expressed as O(N!)
- Board space: O(N²)
- Recursion stack: O(N)
Code issue
 The program does not validate N or firstCol. Invalid input can cause an out-of-bounds access. It also returns only the first solution, not all possible solutions.

P5 — Deterministic and Randomized Quick Sort
File: P5.cpp
What does the program do?
It compares two variations of Quick Sort:
1. Deterministic Quick Sort: always selects the last element as pivot.
2. Randomized Quick Sort: selects a random element as pivot.
Both algorithms sort the array in ascending order. The program also measures their execution time.
Function-by-function explanation
1. partitionDeterministic(vector<int>& arr, int low, int high)

Purpose: Partition the array using the last element as pivot.

How it works:
1. Selects arr[high] as pivot.
2. Initializes i = low - 1.
3. Iterates from low to high - 1.
4. If an element is smaller than or equal to the pivot, moves it to the left partition.
5. Places the pivot in its correct sorted position.
6. Returns the pivot index.
After partitioning:
Elements <= Pivot | Pivot | Elements > Pivot


2. quickSortDeterministic(vector<int>& arr, int low, int high)

Purpose: Sort the array using deterministic Quick Sort.

How it works:
1. Checks whether low < high.
2. Calls partitionDeterministic().
3. Recursively sorts the left subarray.
4. Recursively sorts the right subarray.
3. partitionRandomized(vector<int>& arr, int low, int high)

Purpose: Partition the array using a randomly selected pivot.

How it works:
1. Generates a random index.
2. Swaps the random element with the last element.
3. Uses the last element as the pivot.
4. Performs the same partitioning procedure.
5. Returns the final pivot index.
The random index is generated using:
low + rand() % (high - low + 1);


4. quickSortRandomized(vector<int>& arr, int low, int high)

Purpose: Sort the array using randomized Quick Sort.

It follows the same recursive procedure as deterministic Quick Sort, but uses partitionRandomized().

5. displayArray(const vector<int>& arr)

Purpose: Display all array elements.

It uses a range-based for loop to print each element.

6. main()

Purpose: Run and compare both sorting algorithms.

Steps:
1. Initializes the random number generator using srand(time(0)).
2. Accepts array size and elements.
3. Creates two copies of the original array.
4. Starts the timer for deterministic Quick Sort.
5. Sorts the first array.
6. Stops the timer.
7. Repeats the same process for randomized Quick Sort.
8. Displays both sorted arrays.
9. Displays execution times in microseconds.
Function summary
Function	Purpose
partitionDeterministic()	Partitions using the last element as pivot
quickSortDeterministic()	Performs deterministic Quick Sort
partitionRandomized()	Partitions using a random pivot
quickSortRandomized()	Performs randomized Quick Sort
displayArray()	Displays array elements
main()	Runs both algorithms and compares execution time

Complexity
Case	Quick Sort
Best	O(n log n)
Average	O(n log n)
Worst	O(n²)

- Average recursion space: O(log n)
- Worst recursion space: O(n)
Important: Randomized Quick Sort reduces the likelihood of repeatedly choosing a poor pivot. It does not eliminate the O(n²) worst case.

P12 — Bank Account Smart Contract
File: P12.md
What does the practical do?
Creates a Solidity smart contract that supports:
1. Depositing Ether.
2. Withdrawing Ether.
3. Displaying the contract's balance.
Code explanation
The contract provided in the ZIP is:
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract BankAccount {

    address public owner;
    uint256 private balance;

    constructor() {
        owner = msg.sender;
    }

    function deposit() public payable {
        require(msg.value > 0, "Deposit amount must be greater than 0");
        balance += msg.value;
    }

    function withdraw(uint256 amount) public {
        require(msg.sender == owner, "Only account owner can withdraw");
        require(amount > 0, "Amount must be greater than 0");
        require(amount <= balance, "Insufficient balance");

        balance -= amount;
        payable(owner).transfer(amount);
    }

    function showBalance() public view returns (uint256) {
        return balance;
    }
}


Function-by-function explanation
1. constructor()

Purpose: Initialize the contract.
owner = msg.sender;


Stores the address of the person deploying the contract.

The constructor executes only once during deployment.

2. deposit()

Purpose: Deposit Ether into the contract.
function deposit() public payable


- public: Can be called externally.
- payable: Allows Ether to be sent with the function call.
- msg.value: Amount of Ether received, expressed in Wei.
The require() condition rejects a zero-value deposit.

Then:
balance += msg.value;


Updates the internal balance.

3. withdraw(uint256 amount)

Purpose: Withdraw Ether from the contract.

It checks three conditions:
require(msg.sender == owner, ...);
require(amount > 0, ...);
require(amount <= balance, ...);


These ensure:
- Only the owner can withdraw.
- Withdrawal amount must be positive.
- Sufficient balance must be available.
Then it subtracts the amount and transfers Ether to the owner.

4. showBalance()

Purpose: Return the stored balance.
function showBalance() public view returns (uint256)


- view: Reads contract state without modifying it.
- returns (uint256): Returns an unsigned integer.
The returned amount is in Wei, not automatically ETH.
Function summary
Function / Variable	Purpose
constructor()	Stores contract owner's address
deposit()	Receives Ether
withdraw()	Transfers Ether to owner
showBalance()	Returns internal balance
owner	Stores owner's wallet address
balance	Stores the contract's internal balance

Important Solidity concepts
Keyword	Meaning

uint256	Unsigned 256-bit integer

private	Restricts direct access

Unit conversion:

\]

How it works:

P14 — Survey of Blockchain Types and Real-Time Applications
File: P14.md
What does the practical do?
Studies different types of blockchain architectures, their characteristics, advantages, disadvantages and applications.

There are four main blockchain types in the report.









1. Public Blockchain

Anyone can participate in the network and verify transactions according to its rules.

Examples: Bitcoin and Ethereum.

Uses: Cryptocurrency, DeFi and NFTs.












2. Private Blockchain

Controlled by a single organization. Access is restricted.

Uses: Enterprise records, internal auditing and supply chain management.












3. Consortium Blockchain

Controlled by multiple participating organizations.

Uses: Banking, interbank settlement, trade finance and insurance.












4. Hybrid Blockchain

Combines public verification with private, restricted information.

Uses: Healthcare, government, real estate and supply chain.
